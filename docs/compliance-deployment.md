# 公开部署、健康信息处理与合规配置

核对日期：2026-10-13。本文记录本项目的产品边界和部署前应确认的事项，不是主管部门的定性、备案凭证或上线许可。配置草案见 [compliance-readiness.json](compliance-readiness.json)；它目前是文档，不是应用已经实现的门禁。

## 产品范围按实际功能判断

本项目继续定位为**本人信息整理、健康教育资料查询和就诊材料准备**。观察值只保存原始自述，不解释检查结果；摘要不是诊断病历；警示提示不作诊断、分诊准确率或排除疾病的保证。不提供医师接诊、个体化治疗决策、药物剂量或处方。

是否构成互联网诊疗，不能只看产品名称或加一句免责声明。国家卫健委的制度区分医疗机构的互联网诊疗、互联网医院和远程医疗；开展相应医疗服务要有适用资质与执业安排。[国家卫健委 2018 年文件说明](https://www.nhc.gov.cn/wjw/zccl/201809/410ce29d17494b54bfc07dacd2832f31.shtml)

2022 年细则适用于医疗机构开展互联网诊疗的监管，要求医师实名、由医师本人接诊，医师核对既有诊断资料并判断复诊条件；第二十一条禁止 AI 自动生成处方。未来如果新增医生问诊、临床随访或个体化用药功能，应先重新确认服务性质、机构和人员资格以及适用地方规则，不能用新增 `doctor` 角色代替执业许可。[互联网诊疗监管细则，第 2、13、18、21 条](https://www.nhc.gov.cn/yzygj/c100068/202203/2072f0e8988249e59d942e1b2a933916.shtml)

一般材料提醒不因使用“随访”二字自动构成诊疗；实际疾病监测、治疗调整则不能包装成材料整理。若软件宣称辅助诊断或治疗，还需按预期用途、处理数据和核心功能核实医疗器械分类，不能概括为所有医疗软件都必然属于二类或三类。[国家药监局人工智能医用软件分类界定指导原则](https://www.beijing.gov.cn/zhengce/zhengcefagui/qtwj/202204/t20220408_2669468.html)

## 备案、登记与公示分别配置

《生成式人工智能服务管理暂行办法》覆盖面向境内公众的生成式服务；未向境内公众提供服务的研发、应用不在该办法第二条的适用范围内。第十七条对具有舆论属性或社会动员能力的服务规定安全评估与算法备案义务。因此不能把“所有本机项目均要双备案”写成代码判断，也不能因为是健康准备工具就判定公开服务完全豁免。[暂行办法，第 2、17 条](https://www.cac.gov.cn/2023-07/13/c_1690898327029107.htm)

网信办 2026 年公告明确区分：生成式人工智能服务备案，以及通过 API 或其他方式直接调用已备案模型能力的应用／功能登记。后一类由地方网信办开展登记。已上线应用应公示所使用服务的模型名称、备案号或上线编号；具体路径由运营主体按实际服务向属地确认。[2026-01-09 备案信息公告](https://www.cac.gov.cn/2026-01/09/c_1769688009588554.htm)

算法备案是另一个信息项；完成后应显著展示备案编号并提供公示链接。[算法推荐管理规定，第 24—26 条](https://www.cac.gov.cn/2022-01/04/c_1642894606364259.htm)

建议公开配置至少区分：运营主体、用途、模型名称和服务商、模型服务备案信息、本应用登记信息、适用算法备案信息、官方公示链接、隐私说明、权利申请入口。**没有核实的号码保持空值并显示“未配置／待核实”**；供应商的备案不等于本应用已完成登记。`not_applicable` 也需留存适用性说明，不能用来绕过部署审查。

还需确认生成内容标识：公开生成服务的界面、复制／下载／导出和适用文件元数据均应按实际输出载体落实标识要求。只加一个“AI”页脚不代表全部满足。[人工智能生成合成内容标识办法，第 3—5、14 条，2025-09-01 施行](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)

## 健康信息与同意记录

医疗健康信息属于敏感个人信息。以同意为依据处理时，要清楚告知必要性、目的、数据种类、期限、权益影响和权利途径，取得单独同意，并提供撤回方式；目的、方式或种类变化需重新取得同意。不满十四周岁涉及监护人同意和专门规则。处理敏感信息、委托处理或对外提供前还要开展适用的影响评估。加密和一个勾选框都不能替代这些义务。[个人信息保护法，第 6、14—19、21、28—31、45—47、51、55—56 条](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)

工程配置应保存可核对的告知版本、处理用途、用户的明确选择、同意／撤回时间与生效范围；外部模型发送独立控制，不能被“同意保留记录”一并默认勾选。未同意保存时可提供不持久保存的整理方式，但不得暗中写入数据库、日志或模型缓存。匿名访客的随机 ID 也不是不可识别的法定匿名化。

账号与恢复要遵循最小收集：并不是“真实医疗安全”就必须收集手机号、身份证、微信或建立医生角色。可先实现可恢复账号与可靠授权；若选择手机号／微信登录，另核实平台接入、验证、账号注销、找回与防接管。新增医生角色必须有真实服务需求和资格核验，当前项目不展示“医生已接诊”。

留存天数不能用固定 7 天冒充法定标准。自述准备资料按目的选择最短必要期限，说明备份的期限和删除边界；如果未来转为互联网诊疗，病历与过程记录有不同的法定保管要求，不能照搬演示库自动清理策略。撤回后应停止相应处理并按适用规则删除或限制处理；导出不得带出其他账号资料、密钥或会话凭证。

## 本机模型与云 API 的数据边界

本机模型有利于减少第三方传输，但不自动满足所有合规要求。境内 API 也不自动构成数据出境。应确认实际处理／存储地区、运维访问地、日志和训练使用、子处理商及备份；境内保存而境外能够查询、调取、下载或导出的场景也需核查出境规则。[网信办数据出境政策问答（2025 年 10 月），第 5 问](https://www.cac.gov.cn/2025-10/31/c_1763633376984070.htm)

受托处理、提供给独立个人信息处理者与跨境提供的责任不同。应按实际合同和数据流确认处理角色、允许用途、期限、删除、转委托与安全责任；不是取得一次用户授权就可以无限发送。真的发生跨境时，按适用条件确认告知、单独同意、影响评估及出境制度；豁免某项出境程序不代表免除保护义务。[促进和规范数据跨境流动规定，第 5、7—11 条](https://www.cac.gov.cn/2024-03/22/c_1712776611775634.htm)

公开展示只提供经确认的服务商、模型及数据说明；API Key、私钥、密钥路径、数据库连接、内部报告和原始健康正文不进入公示配置。

## 等保和工程验收边界

等级保护按系统作用、重要程度与被破坏后的影响确定。**并非只要有健康信息就能直接认定“二级起步”**。运营主体应按实际系统定级并完成适用备案、建设整改和测评；互联网诊疗的省级监管平台和医疗机构诊疗平台，2022 年细则第三十三条另要求三级及以上。[信息安全等级保护管理办法，第 7、10、14—17 条](https://www.miit.gov.cn/jgsj/xxjsfzs/xxgk/art/2020/art_a981907528694176a61b5b52c2d19895.html)；[互联网诊疗监管细则，第 33 条](https://www.nhc.gov.cn/yzygj/c100068/202203/2072f0e8988249e59d942e1b2a933916.shtml)

开发方可以实现加密、身份权限、同意撤回、导出删除、迁移、备份恢复、指标、限流和部署门禁；不能用测试通过来声称主管部门备案、临床验证、等保测评或医疗机构资格已经获得。公开真实数据部署应由运营主体核对上述适用事项，留存外部手续与技术验收证据后另行批准。

本文不是对本次并行开发结果的验收。当前实现状态以对应提交、测试报告和实际运行服务为准；草案里标注 `verified` 的形式校验仅检查字段齐全，不鉴别凭证真伪，也不代表主管部门批准。
