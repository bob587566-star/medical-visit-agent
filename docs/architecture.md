# 健康沟通工作台 V2 · 结构与边界

## 数据流

浏览器先取得访客 Cookie 与 CSRF Token。填表、对话、清单和摘要均属于该访客；后端每次用 owner + record ID 共同查找，而不是仅凭记录 ID 授权。

六个页面共享同一份 Visit。总览使用实际持久化数量，资料收藏按访客隔离；旧记录缺少 V2 字段时用 schema 默认值兼容加载。

七项基础字段决定采集阶段，备注可选。一次提供一个焦点问题，已经确认字段的旧问题不会接收下一项短答。候选保留原文与后端 ID，不自动写入；确认接口只使用后端保存的候选值，确认后消费候选。编辑表单使旧候选失效。未确认候选不进入事实摘要或个人准备计划。

观察保存原始数值、类型、单位、发生时间及备注，按带时区的实际时间排序。无时区时间按本项目 UTC+8 解释。只整理，不解释测量含义；症状观察先区分旧记录与当前报告后执行有限警示规则。计划为材料整理和沟通步骤，不是治疗方案。

对话先执行当前警示检查；紧急分支返回本机提示。普通问题查询人工整理资料，再整理自述、清单和摘要。外部模型只在显式 `use_model=true` 时参与受限摘录，返回值必须通过结构校验且是允许发送文本中的连续片段。未知问题不借用旧填表内容来假装检索命中。

`knowledge/articles.json` 保存 37 篇、6 类资料、来源链接、出版方与核对日期。主题过滤限制候选范围，BM25 在范围内排序；可选 HybridRetriever 固定访问本机 Ollama 生成公共资料和问题向量，融合排名。验证模型、向量数值、维数、重定向与内容变化；缓存按内容哈希和模型 digest 失效，只保存公共资料向量，不保存个人问句。离线明确显示 lexical_fallback，实际可用显示 hybrid_ollama。资料格式错误时不继续服务旧内容，不把排名当作医学置信度。

## 并发与持久化

HTTPX 异步调用模型，调用期间不持有数据库提交锁。紧急提醒不排在模型请求后。每次回复提交前重新读取记录，保留其他并发提交；已删除的记录不会被慢回复重建。若资料更新，风险按最新表单重算，不能被旧结果降级；尚未解决的紧急提示不能被问候或保存表单清除。摘要生成时若表单、对话或观察变化，返回冲突让用户重试；勾选状态提交时合并保留。修改表单、确认候选和编辑时间线使旧摘要与计划失效。

当前是单进程 SQLite 实现，锁只在当前进程生效；不能据此声称多实例一致性或高可用。摘要与清单属于准备资料，不是病历诊断。

## 防护

- 随机会话 Cookie、所有修改接口 CSRF 校验、Origin 校验、访客归属隔离。
- 64 KiB 请求限制、字段长度限制、记录/对话数量限制、普通请求频率限制。
- JSON 校验错误不回显原始输入；后台启动关闭访问日志，避免搜索词进入 URL 日志；不记录正文和密钥。
- 前端使用文本插值，来源链接限制协议；同源 CSP、禁止 iframe 嵌入、API 禁止缓存。
- 本机记录可删除、过期清理；数据库未加密，当前只适合虚构演示数据。

规则和测试覆盖的是列出的工程行为；文本警示规则有覆盖范围，不能作为医疗分诊系统验证。
